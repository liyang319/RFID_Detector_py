# 生产信息码生成与转换规则

> 适用范围：`processes/gui_process.py` 的 `create_product_code()`（生成明文）与 `create_code_encode()`（转 hex）。
> 本文件与 `KNOWLEDGE.md` 一致，作为编码规则的权威说明；修改代码后需同步更新两处。

---

## 一、生产信息码（明文，28 位）生成规则

### 1.1 数据来源（`create_product_code`）

| 明文位置 | 位数 | 内容 | 数据来源 |
|---------|------|------|---------|
| 第 1-5 位 | 5 | 产品码(3) + 工厂代码(2) | `config/business.json` → `products[].code` + `factory.code` |
| 第 6-8 位 | 3 | 生产许可证后 3 位 | `factory.license`（如 `MB140` → `140`） |
| 第 9-11 位 | 3 | 规格型号（型号 2 位 + 字母 1 位） | GUI `typeBox`（如 `24L`） |
| 第 12 位 | 1 | 包装方式字母 | GUI 包装单选：箱装(`radioButton_2`)→`X`，否则→`D` |
| 第 13-14 位 | 2 | 净重 | GUI `comboBox` |
| 第 15-20 位 | 6 | 生产日期（YYMMDD） | GUI `productionDate`（如 `240803`） |
| 第 21-24 位 | 4 | 生产批号 | GUI `batchNumber`（如 `0001`） |
| 第 25-28 位 | 4 | 生产袋/箱号 | GUI `packageNumber`（如 `0001`） |

### 1.2 拼接顺序

1. `products[当前索引].code`（产品码，3 位）
2. `factory.code`（工厂代码，2 位）
3. `factory.license[2:]`（许可证后 3 位）
4. `typeBox_data`（规格型号，3 位）
5. `"X" if box else "D"`（包装字母，1 位）
6. `weigt_data`（净重，2 位）
7. `productionDate`（日期，6 位）
8. `batchNumber`（批号，4 位）
9. `packageNumber`（袋/箱号，4 位）

### 1.3 校验规则

- 生产日期长度 == **6**
- 生产批号长度 == **4**
- 生产袋/箱号长度 == **4**
- 产品/工厂/型号/净重/包装单选均需有值

## 二、生产信息码 → 待写入代码（hex）转换规则

### 2.1 分段编码（`create_code_encode`，共 19 字节 = 38 位 hex）

| 明文位置 | 明文内容 | 编码方式 | 字节数 |
|---------|---------|---------|--------|
| `[0:5]` | 产品码 + 工厂代码 | ASCII 直接编码 | 5 |
| `[5:8]` | 许可证后 3 位 | 十进制串 → `int` → 大端 2 字节 | 2 |
| `[8:10]` | 型号（2 位数字） | 十进制串 → `int` → 1 字节 | 1 |
| `[10]` | 规格型号第 3 位字母（如 `L`） | ASCII | 1 |
| `[11]` | 包装方式字母（`D`/`X`） | ASCII | 1 |
| `[12:14]` | 净重 | ASCII | 2 |
| `[14:20]` | 生产日期 | 每 2 位数字 → 1 字节，共 3 段 | 3 |
| `[20:24]` | 生产批号 | 每 2 位数字 → 1 字节，共 2 段 | 2 |
| `[24:28]` | 生产袋/箱号 | 每 2 位数字 → 1 字节，共 2 段 | 2 |

### 2.2 关键编码方式说明

- **ASCII 段**：字符串每个字符按 ASCII 码 1 字节（大写 hex）。
- **数字段**：`int(十进制串).to_bytes(N, 'big')`，固定 N 字节大端（前导 0 保留）。
- **"每 2 位→1 字节"**（日期/批号/箱号）：如 `250803` → `25`→`0x19`、`08`→`0x08`、`03`→`0x03` → hex `190803`；`9999` → `99`→`0x63`、`99`→`0x63` → `6363`。

### 2.3 写码指令

38 位 hex → `bytes.fromhex(...)`（19 字节）→ 十进制列表 → 发送：

```json
{"type": "write_user", "user_data": [十进制字节列表]}
```

（见 `gui_process.py` `handle_cargo_in` → `NETWORK_DATA_SEND`）

## 三、完整示例

### 乳化炸药（袋装 D）
- 来源：产品码 `07X`、工厂 `D6`、许可证 `MB140`、型号 `30L`、净重 `30`、日期 `240803`、批号 `0001`、箱号 `0001`
- 明文：`07XD614030LD3024080300010001`（28 位）
- 分段 hex：
  - 产品+工厂 `07XD6` → `3037584436`
  - 许可证 `140` → `008C`
  - 型号 `30` → `1E`、字母 `L` → `4C`、包装 `D` → `44`、净重 `30` → `3330`
  - 日期 `240803` → `18 08 03`
  - 批号 `0001` → `00 01`、箱号 `0001` → `00 01`
- 待写入：`3037584436008C1E4C44333018080300010001`（19 字节）

### 高密度震源药柱（箱装 X）
- 来源：产品码 `47X`、工厂 `D6`、许可证 `MB140`、型号 `24L`、净重 `24`、日期 `240803`、批号 `0001`、箱号 `0001`
- 明文：`47XD614024LX2424080300010001`（28 位）
- 待写入：`3437584436008C184C58323418080300010001`（19 字节）

## 四、相关产品/包装规则（联动）

- 设备输入模式下：日期/批号只读；**乳化炸药/粘性炸药**的生产箱号可编辑，其余产品箱号只读。
- 产品每通过一次（`cargo_out`）：生产箱号 +1（4 位补零，超 `9999` 回到 `0001`），仅乳化炸药/粘性炸药生效。
- 产品类型由 `config/business.json` 的 `products[].name` 提供（乳化炸药、粘性炸药、起爆具、高爆速震源药柱、高密度震源药柱）。
- 「生产状态」组：`产品进入`、`代码写入`、`产品通过` 三者 UI 一致（均为 QRadioButton），布局顺序为 `产品进入→代码写入→产品通过`，三者等间隔；全部 `setEnabled(False)` 不可手动选中（`setAutoExclusive(False)` 允许设备独立勾选），由设备事件驱动：`cargo_in`→勾选`产品进入`+`代码写入`，`cargo_out`→勾选`产品通过`+`代码写入`。
